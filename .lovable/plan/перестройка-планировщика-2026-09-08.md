# Перестройка планировщика

## Что получится

Вместо четырёх рядов управления — два: слева переключатель вида (Люди / Доска / Календарь / Список), справа кнопка «Новая задача» с меню (там же «Шаблоны»); под ним одна строка фильтров: Период, Объект, Техника, Приоритет, Исполнитель + поиск и группировка.

Вид «Люди» открывается по умолчанию: колонки по сотрудникам, крайняя левая — «Не распределено» (задачи без исполнителя + заявки, по которым ещё нет ни одной задачи, с плашкой «из заявки»). Перетаскивание карточки в колонку человека назначает исполнителя мгновенно, с тостом и кнопкой «Отменить» (5 секунд).

## Ответы на вопросы из задания

- **Справочник исполнителей.** Уже есть: `usePlannerMembers()` — активные сотрудники организации с доступом к планировщику (`is_active` + `planner_access`), а не общий список людей. Именно он станет источником колонок вида «Люди» и списка в фильтре «Исполнитель».
- **Связь задача–заявка.** Есть: у задачи есть поле «заявка» (`planner_tasks.request_id`). Обратный запрос «заявки без задач» строится и уже проверен: сейчас в базе 1682 заявки, из них 1099 без единой задачи. Чтобы колонка «Не распределено» не превращалась в свалку, в неё попадут только активные (не завершённые и не архивные) заявки, отсортированные по сроку, с ограничением и кнопкой «показать ещё».
- **Перетаскивание.** Библиотека уже в проекте: `@dnd-kit/core` + `@dnd-kit/sortable` (используется на доске). Ничего ставить не нужно.
- **Полоса загрузки (баг).** Сейчас нагрузка считается как «активные задачи / 15», результат обрезается до 100%. У сотрудника с 97 задачами получается ровные 100% и зелёный вид. Полоса будет показывать долю просрочки, число задач выводится рядом, и при просрочке больше трети колонка, полоса и число становятся красными.

## Этапы

1. **Каркас управления** — два ряда, 4 вида, меню «Новая задача / Шаблоны», фильтр «Период», редиректы старых адресов. ~7–9 кредитов.
2. **Вид «Люди»** — колонки, шапки с корректной загрузкой и цветами просрочки, колонка «Не распределено» с задачами без исполнителя. ~9–12 кредитов.
3. **Заявки без задач и перетаскивание** — плашка «из заявки», назначение исполнителя перетаскиванием, тост с «Отменить» на 5 секунд, создание задачи из заявки при переносе. ~8–10 кредитов.
4. **Доводка** — группировка по объектам/технике во всех видах, мобильный вид, проверка прав доступа. ~5–7 кредитов.

Итого ориентировочно 30–38 кредитов. Этапы можно останавливать после любого: после первого планировщик уже станет двухрядным.

## Технические детали

- Период реализуется предикатом над `due_date` (сегодня / неделя / просрочено / всё) в `PlannerFiltersContext.apply`, чтобы все виды использовали один датасет.
- «Заявки без задач»: `select ... from requests where organization_id = :org and id not in (select request_id from planner_tasks where request_id is not null)`, с фильтром по активным статусам и лимитом; на клиенте — отдельный react-query ключ, инвалидируется вместе с `planner-tasks`.
- Перетаскивание: `DndContext` на странице «Люди», `useDroppable` на колонке, drag-карточки; drop задачи → `updatePlannerTask({assignee_id})` с optimistic update; drop заявки → создание задачи со ссылкой на заявку и исполнителем.
- Метрика шапки: `overdueShare = overdue / activeTotal`; полоса = `overdueShare`, красный при `> 1/3`; счётчик задач показывается числом, а не долей от условной нормы 15.
