
## Цель
Добавить в Планировщик вторую независимую вкладку **«Мой план»** — личный ежедневник, не связанный с автоматическими CRM-задачами. Существующая вкладка «Сегодня» становится разделом «Авто-задачи» (из CRM), а «Мой план» — отдельная зона для ручных задач сотрудника.

## Структура навигации
Верхние вкладки Планировщика:
1. **Авто-задачи** (`/planner` — текущая страница «Сегодня» из CRM-триггеров) — переименовать пункт в "Авто-задачи"
2. **Мой план** (`/planner/my`) — новая вкладка с под-навигацией: Сегодня · Завтра · Эта неделя · Следующая неделя · Календарь · Список
3. Остальные пункты (Обзор, Задачи, Доска, Календарь, План по времени, Этапы, Шаблоны) остаются как есть.

Разделение в БД: `planner_tasks.source = 'auto_rule'` — авто, `source = 'manual'` (default) — личные. Личные задачи не попадают в авто-вкладку и наоборот.

## Поля задачи (форма создания/редактирования)
Расширяем существующий `PlannerTaskDialog`:
- название (есть)
- описание (есть)
- **дата выполнения + время выполнения** (новое поле `due_time` или использовать таймштамп в `due_date`)
- срок окончания (есть — `due_date`)
- приоритет: Критический/Высокий/Средний/Низкий (есть; добавляем `critical`)
- объект (есть, `object_id`)
- техника (есть, `equipment_id`)
- исполнитель (есть)
- напоминание (есть таблица `planner_task_reminders` — добавить UI)
- повторение (есть `recurrence`)
- чек-лист (есть)
- вложения (есть)
- комментарии (есть)

В меню карточки добавить пункт «Преобразовать в заявку CRM» — заглушка-кнопка, открывает существующий `CreateRequestDialog` с предзаполнением `title/description`. Если задача уже привязана к заявке (`request_id`), показывать ссылку на заявку.

## Технический план

### 1. Миграция БД
- Добавить колонку `due_time time` в `planner_tasks` (для отдельного времени; `due_date` остаётся датой/таймштампом окончания).
- Убедиться, что `priority` принимает `critical` (если CHECK constraint — обновить).
- Установить default `source = 'manual'` для ручных задач (уже есть поле).
- Фильтр для существующих хуков и страниц авто-вкладки: где надо — фильтр `source = 'auto_rule'`, где «Мой план» — `source <> 'auto_rule' OR source IS NULL`.

### 2. Хуки
- Обновить `usePlannerTasks` — добавить опциональный параметр `{ scope: 'manual' | 'auto' | 'all' }`.
- Тип `PlannerTaskPriority` — добавить `'critical'` и стиль в `PRIORITY_META`.

### 4. Существующие файлы
- `src/pages/planner/PlannerLayout.tsx` — переименовать «Сегодня» → «Авто-задачи»; добавить пункт «Мой план».
- `src/App.tsx` — роуты `/planner/my/*`.
- `src/pages/planner/PlannerToday.tsx` — фильтр `source = 'auto_rule'` (он и так оперирует авто-блоками, но убедимся).
- `src/components/planner/PlannerTaskDialog.tsx` — добавить поле «Время», приоритет «Критический», секции «Напоминание» (если ещё нет UI).
- `src/hooks/usePlannerTasks.ts` — расширить тип и фильтрацию.

### 5. Без бэкенд-побочки
Триггер `sync_request_to_planner` уже ставит `source='auto_rule'` — ручные задачи останутся `'manual'` и в авто-вкладке не появятся.

## Ограничения / решения по умолчанию
- Время задачи храним в новом `due_time` (типа `time`), чтобы не ломать существующие сортировки по `due_date`.
- Напоминания пишем в существующую `planner_task_reminders` (UI добавим простой: за 15 мин / 1 час / 1 день / своё).
- «Преобразовать в заявку CRM» — заглушка-кнопка (открытие `CreateRequestDialog` с предзаполнением). Полноценная синхронизация — отдельный этап.

## Что НЕ делаем в этой итерации
- Не меняем логику авто-триггеров.
- Не трогаем `PlannerKanban`/`PlannerTimeline`/`PlannerStages` — они общие.
- Push-уведомления по напоминаниям — оставляем как задел (cron уже есть `planner-cron`).
