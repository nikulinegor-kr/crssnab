# Переработка модуля Planner

Большой объём работы — разобью на 4 этапа. После каждого этапа можно остановиться и проверить результат, прежде чем двигаться дальше.

---

## Этап 1. Фундамент: данные + страница «Сегодня» + автогенерация задач

### 1.1. Миграция БД (расширение `planner_tasks`)

Добавить поля:
- `source` (text) — `manual` / `crm_request` / `auto_rule`
- `source_request_id` (uuid, FK → requests) — связь с заявкой
- `source_rule` (text) — какое правило породило задачу (`emergency_request`, `invoice_pending`, `delivery_due`, `arrival_receipt`, `status_stale`)
- `priority` (text) — `critical` / `high` / `medium` / `low` (привести существующие значения)
- `due_at` (timestamptz) — срок выполнения
- `delegated_to` (uuid) — кому делегировано (отдельно от assignee для отчёта руководителя)
- `recurrence` (jsonb) — `{ type: 'daily'|'weekly'|'monthly'|'weekdays', days?: [1..7], until?: date }`
- `last_auto_sync_at` (timestamptz) — для идемпотентной автогенерации

Уникальный индекс `(organization_id, source_request_id, source_rule)` чтобы не плодить дубли.

### 1.2. Таблица напоминаний

`planner_task_reminders`: `task_id`, `offset_minutes` (1440 / 120 / 30 / 0=просрочка), `sent_at`, `channel` (`app`/`telegram`/`max`).

### 1.3. Триггеры синхронизации CRM ↔ Planner

Триггер на `requests`:
- Аварийная заявка → задача `Согласовать аварийную заявку` (priority=critical, assignee=руководитель).
- Появился `invoice_number` без оплаты → задача бухгалтеру (Казакова) `Оплатить счёт №...`.
- `delivery_date` ≤ сегодня+1 → задача исполнителю `Контроль поставки`.
- Статус = «Доставлено» → задача `Провести приёмку ТМЦ`.
- Статус не менялся > 5 дней → задача `Проверить заявку без движения`.
- Закрытие заявки (`Доставлено`/архив) → автоматически закрываются связанные авто-задачи.
- Смена исполнителя → `assignee_id` авто-задачи обновляется.

Всё через идемпотентный `upsert` по `(source_request_id, source_rule)`.

### 1.4. Страница «Сегодня» (`/planner/today`, по умолчанию при входе в `/planner`)

4 блока с агрегацией заявок + задач:
- 🔴 **Срочно** — аварийные/просроченные заявки + задачи priority=critical.
- 🟠 **Требуют внимания** — счета >N дней в бухгалтерии, без поставщика/ТК/даты отгрузки/исполнителя/комментариев.
- 🟢 **План на сегодня** — мои задачи на сегодня (assignee=я, due_at=today) + ручные.
- 🔵 **Делегировано** — задачи где `delegated_by=я`, разбивка по сотрудникам, %выполнения, просрочки.

Каждая карточка кликабельна → открывает заявку или модалку задачи.

## Этап 2. Приоритеты, быстрые действия, мобильная карточка

### 2.1. Цветовая система приоритетов
Единые токены: critical=red, high=orange, medium=blue, low=muted. Бейджи + левая полоса карточки.

### 2.2. Карточка задачи (mobile-first)
- Название, бейдж приоритета, срок (с цветом просрочки), исполнитель, бейдж источника (CRM/manual).
- Крупные тач-таргеты (min-h-12).

### 2.3. Быстрые действия (inline, без модалки)
- ✅ Выполнить, ⏰ Отложить (+1д/+1ч/завтра), 👤 Передать (popover со списком сотрудников), 💬 Комментарий (inline-textarea), 🔗 Перейти в заявку.

## Этап 3. Представления + повторяющиеся задачи + уведомления

### 3.1. Переключатель представлений
Tabs: Сегодня / Неделя / Месяц / Канбан / Календарь / По сотрудникам. Часть уже есть — добавить «Неделя» и «По сотрудникам», унифицировать навигацию.

### 3.2. Повторяющиеся задачи
- Поле `recurrence` в форме задачи.
- Edge-функция `planner-recurrence-cron` каждые сутки создаёт следующий инстанс.

### 3.3. Напоминания
- Edge-функция `planner-reminders-cron` каждые 5 минут: ищет задачи с подходящим offset и пишет в `notifications` (app), потом — Telegram/MAX через существующий `notification-worker`.

## Этап 4. AI-помощник Planner

### 4.1. Edge-функция `planner-daily-brief`
- Собирает снапшот: мои задачи, делегированные, аварийные заявки, счета, нагрузка по исполнителям.
- Модель `google/gemini-3-flash-preview` через Lovable AI.
- Возвращает Markdown-резюме «План на сегодня».

### 4.2. Виджет на странице «Сегодня»
- Карточка сверху: кнопка «Сформировать план дня», результат рендерится через `react-markdown`.
- Автоматический вызов при первом открытии страницы за день (кэш в `ai_analytics_reports`).

## Технические детали

- БД: миграция расширения `planner_tasks`, новая таблица `planner_task_reminders`, триггеры на `requests` (`SECURITY DEFINER`, `search_path=public`).
- Идемпотентность авто-задач — уникальный индекс + `ON CONFLICT DO UPDATE`.
- Edge-функции: `planner-daily-brief` (AI), `planner-reminders-cron` (pg_cron каждые 5 мин), `planner-recurrence-cron` (раз в сутки).
- Frontend: новая `/planner/today` как индекс `PlannerLayout`; переиспользовать `useAnalyticsRequests` для агрегатов; компоненты `TaskCard`, `QuickActions`, `PriorityBadge`, `DueBadge`.
- Cron-задания регистрируются через `supabase--insert` (не миграция, т.к. содержат URL и anon key).

## Что НЕ входит в эту итерацию

- Полноценная отправка push на мобильный (только запись в `notifications`).
- Интеграция Telegram/MAX-кнопок для быстрых действий из бота (запишу как следующий шаг).
- Drag-and-drop задач между сотрудниками в режиме «По сотрудникам» — сделаю простой select.
